# 2026.Multi.Public
# Regional Precipitation Forecasting with Foundation Models via a Multi-Agent System

This repository contains the research code, configuration, and a synthetic
sample dataset that accompany the manuscript *"Regional Precipitation
Forecasting with Foundation Models: A Multi-Agent Benchmark over Eight KMA
ASOS Stations (2001–2025)"*. Every figure and table reported in the paper
can be reproduced from the source code under `src/` and the configuration
in `config/config.yaml`, given access to the original Korea Meteorological
Administration (KMA) observations.

A self-contained quick test (`examples/quick_test.py`) runs the full
pipeline on synthetic data in roughly one minute on a laptop CPU.

---

## 1. Purpose of the Research Code

The goal of this project is to provide a **fully reproducible benchmark**
of modern time-series Foundation Models (TimesFM 2.5, Chronos-2,
Moirai 1.0, TTM) against a classical statistical baseline (SARIMAX) and a
localized deep-learning baseline (LSTM) for **monthly precipitation
forecasting** at eight major Korean synoptic stations.

The code automates:

* Quality control and **VIF-based feature curation** of hydro-meteorological
  predictors;
* Four feature-engineering strategies — All variables (V1_ALL),
  Mutual-Information selection (V2_FS), PCA (V3_PCA), and Factor Analysis
  with Varimax rotation (V4_FA);
* Six forecasting models trained and evaluated under an identical
  expanding-window protocol;
* Aggregated evaluation over six metrics (RMSE, MAE, PBIAS, R², NSE, KGE)
  and eight evaluation periods (full, four seasons, top-1/2/3 extreme
  months);
* Final model selection via the **average ranking method**.

Total experimental matrix: **6 models × 4 feature settings × 8 stations =
192 experiments**.

## 3. Runtime Environment

The pipeline has been verified on the following stack. A close superset
should work; the foundation-model packages in particular benefit from a
CUDA-capable GPU for realistic runtimes.

| Component | Version used |
|-----------|--------------|
| OS        | Windows 10/11 (PowerShell) or Linux / WSL 2 |
| Python    | 3.10 or 3.11 |
| CUDA      | 11.8 (for the foundation models; optional for the quick test) |
| GPU       | NVIDIA GPU ≥ 12 GB VRAM (RTX 3060 or better) — only for foundation models |
| RAM       | 16 GB minimum, 32 GB recommended |
| Disk      | ≥ 20 GB free for outputs and model caches |

Core Python dependencies (pinned in `requirements.txt`):

```
numpy==1.26.4
pandas==2.2.2
scikit-learn==1.4.2
statsmodels==0.14.2
factor_analyzer>=0.5.1
PyYAML>=6.0
joblib>=1.3
matplotlib==3.8.4
torch==2.2.1
```

**Foundation-model packages** (install separately; see §4):

```
chronos-forecasting>=2.0          # Chronos-2
uni2ts>=1.2                        # Moirai 1.0
timesfm>=2.5                       # TimesFM 2.5
tsfm-public>=0.2                   # Tiny Time Mixer (TTM)
```

The CPU-only quick test in `examples/quick_test.py` runs without any of
the foundation-model libraries; the wrappers fall back to a covariate-
augmented linear in-context regressor when the heavyweight package is
unavailable, so the whole pipeline still executes end to end.

## 4. Installation

```bash
git clone https://github.com/<your-org>/2026.01.Anti.Predict.Multi.git
cd 2026.01.Anti.Predict.Multi

# 1. create and activate a virtual environment
python -m venv .venv
# Windows PowerShell:  .\.venv\Scripts\Activate.ps1
source .venv/bin/activate

# 2. install the core scientific stack
pip install -r requirements.txt

# 3. (optional) install foundation-model packages
pip install timesfm                       # TimesFM 2.5
pip install chronos-forecasting           # Chronos-2
pip install "uni2ts>=1.2"                 # Moirai 1.0
pip install "tsfm-public>=0.2"            # Tiny Time Mixer

# 4. sanity-check the install
python -c "import torch, pandas, statsmodels, yaml; print('OK')"
```

Each foundation-model package downloads several hundred MB of model
weights the first time it is invoked. Plan disk space accordingly.

## 5. Data Preparation

The original KMA ASOS observations are **not** redistributed in this
repository (see §9). Two paths are supported:

### (a) Reviewer / quick reproduction — synthetic sample

A synthetic monthly dataset that follows the same column layout as the
real KMA files lives at `data/sample/`. It is generated on demand by:

```bash
python examples/make_synthetic_data.py
```

The synthetic generator produces a 25-year (2001-2025) monthly record for
the eight stations with a 12-month seasonal cycle, station-specific
offsets, and Gaussian noise. It is sufficient to exercise every code path
but **must not** be interpreted as representative of real precipitation.

### (b) Full reproduction — real KMA data

1. Register for the KMA Open MET Data Portal:
   <https://data.kma.go.kr/>.
2. Request access to *ASOS 일자료* (daily) and *ASOS 월자료* (monthly).
3. Download the variables listed at the top of `src/preprocess_data.py`
   for stations 105, 108, 112, 133, 143, 146, 156, 159.
4. Place the cp949-encoded CSVs in `data/raw/` with the file names
   declared under `data:` in `config/config.yaml`:

   ```
   data/raw/OBS_ASOS_DD_2001.2010.csv
   data/raw/OBS_ASOS_DD_2011.2020.csv
   data/raw/OBS_ASOS_DD_2021.2025.csv
   data/raw/OBS_ASOS_MNH_2001.2025.csv
   ```

After step 4 the full workflow (§7) reproduces every table and figure of
the manuscript.

> The original KMA data are licensed for non-commercial research and
> educational use with attribution; see §9 for the redistribution
> restriction.

## 6. Quick-Test Execution

The quick test demonstrates that the environment is healthy and that the
pipeline produces sensible outputs **without** the raw KMA data or the
heavy foundation-model packages.

```bash
python examples/quick_test.py
```

What it does (≈ 30–90 s on a laptop CPU):

1. Generates `data/sample/` if it does not already exist;
2. Runs preprocessing, lag construction, VIF screening, V2_FS, and
   PCA / FA fitting on the synthetic data;
3. Trains and evaluates SARIMAX **and** the TimesFM XReg fallback on
   one station (Seoul) using one feature setting (V1_ALL);
4. Writes:

```
outputs/quick_test/predictions.csv   # observed + predicted, monthly
outputs/quick_test/metrics.csv       # RMSE, MAE, PBIAS, R², NSE, KGE
outputs/quick_test/figures/          # heatmap + hydrograph PNGs
outputs/quick_test/tables/           # average-rank and per-metric tables
```

A successful run prints a summary table similar to:

```
 Model Setting Station   RMSE    MAE   PBIAS    R2    NSE   KGE
SARIMAX V1_ALL  Seoul    36.5  28.9   -3.1   0.49  0.41  0.62
TimesFM V1_ALL  Seoul    38.0  30.2   -1.8   0.46  0.39  0.60
```

Exact values vary slightly because the synthetic generator and SARIMAX
both rely on stochastic components.

## 7. Full Workflow Execution

After populating `data/raw/` with the real KMA CSVs (see §5b), run the
twelve scripts in order. Each is idempotent and writes to a distinct
subdirectory under `outputs/`.

```bash
# --- Stage A: data and feature engineering ---
python -m src.preprocess_data
python -m src.construct_covariates
python -m src.vif_screening
python -m src.feature_selection
python -m src.pca_factor_analysis

# --- Stage B: model training (expanding window, 60 one-step forecasts) ---
python -m src.run_sarimax       # 32 CSVs
python -m src.run_lstm          # 32 CSVs
python -m src.run_timesfm       # 32 CSVs
python -m src.run_chronos       # 32 CSVs
python -m src.run_moirai        # 32 CSVs
python -m src.run_ttm           # 32 CSVs
                                # → 192 prediction CSVs total

# --- Stage C: evaluation and figures ---
python -m src.evaluate_models
python -m src.make_figures_tables
```

Approximate runtime on a single RTX 3090 (24 GB): **6–9 hours**
end-to-end, dominated by the foundation-model stage.

A directory-by-directory crosswalk between manuscript sections and source
files lives in `docs/workflow_overview.md`.

## 8. Main Output Description

After a full run, the following artifacts are produced under `outputs/`:

| Path | Contents | Count |
|------|----------|------:|
| `outputs/preprocessed/`        | Train / test monthly tables with the curated predictors | 3 |
| `outputs/variable_selection/`  | VIF table, V2_FS ranking, PCA / FA loadings + saved transformers | 8+ |
| `outputs/monthly/`             | Per-experiment 60-step forecasts (`{Model}_{Setting}_{Station}.csv`) | 192 |
| `outputs/tables/`              | `all_metrics.csv`, `average_rank.csv`, `best_model_per_station.csv` | 3 |
| `outputs/figures/`             | Metric heatmaps and best-model hydrographs | 12+ |

Key outputs referenced in the manuscript:

* `outputs/tables/average_rank.csv` — the average-rank table that drives
  the final model-selection conclusion (Section 4);
* `outputs/tables/best_model_per_station.csv` — the data behind the
  best-model spatial map (Figure 7);
* `outputs/figures/metric_heatmap_KGE.png` — model × feature heatmap of
  the headline KGE values;
* `outputs/figures/hydrograph_<station>.png` — per-station hydrographs
  comparing observed vs. predicted monthly precipitation.

The reference quick-test outputs that ship with the repository sit under
`outputs/quick_test/predictions.csv` and `outputs/quick_test/metrics.csv`.

## 9. Raw Data Access Restriction

The raw daily and monthly precipitation observations used in the
manuscript are sourced from the **Korea Meteorological Administration
(KMA) Open MET Data Portal** (<https://data.kma.go.kr/>). Per the KMA
terms of service:

* The observations are made available for **non-commercial research and
  educational use** with attribution to KMA.
* **Redistribution of the raw CSV files to third parties is restricted**
  by the data provider. To keep this repository compliant, the raw files
  are **not** included; only synthetic data of identical shape is
  shipped under `data/sample/`.
* No personal, proprietary, or otherwise sensitive information is
  contained in the dataset; all variables are station-level
  meteorological observations.
* The preprocessing scripts in `src/preprocess_data.py` work against
  either the synthetic sample or an independently downloaded copy of the
  KMA files placed in `data/raw/` (see §5b).

All derived artifacts (preprocessed tables, model forecasts, evaluation
tables, figures) generated from synthetic data and shipped with this
repository are released under the same license as the source code.
